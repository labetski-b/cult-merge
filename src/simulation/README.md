# AI Simulation

Симулятор прогона игры без UI. Запускается на `localhost:5180/cult-merge/simulation.html`.

## Архитектура

```
main.ts                    — UI дашборда, запуск симуляции
engine/SimulationEngine.ts — движок: тики, выполнение действий, метрики
engine/types.ts            — типы (SimulationAction, AIStrategy, метрики)
engine/metrics.ts          — захват метрик по тику
strategies/               — стратегия AI-игрока
```

## SimulationEngine

Каждый тик:
1. Если `meat < 5` — автоматически добавляет +10 meat
2. Вызывает `strategy.decide(state, rng)` → получает список действий
3. Выполняет действия последовательно (каждое мутирует state)
4. Сохраняет снапшот с метриками

Действия выполняются **в порядке очереди**. Каждое действие видит state после предыдущих.

### Доступные действия

| Action | Что делает |
|--------|-----------|
| `claim_reward` | Забирает первую награду из `pendingRewards` (яйцо генератора, бокс) |
| `charge_generator` | Тратит meat, генерирует заряды (15 при level 1) |
| `spawn_generator` | Достаёт один заряд → создаёт существо в свободной ячейке |
| `feed` | Убирает существо с поля → +EXP, прогресс по заданию |
| `merge` | Два существа/генератора одного типа и уровня → одно уровнем выше |
| `open_box` | Достаёт руну из бокса |
| `buy_generator_1` | Покупает Generator 1 level 1 за rune1 (стоимость из `purchaseCost`) |

### Важные механики
- `spawn_generator` спавнит **одно существо за вызов** (один заряд). Чтобы спавнить все 15, нужно 15 действий
- `feed` всегда даёт EXP, независимо от задания. Если существо подходит под задание — ещё и прогресс по нему
- `merge` работает и для существ (level < 9), и для генераторов (level < 5)
- Сетка начинается как 2x4 = 8 ячеек. Растёт при левел-апе

## RealisticStrategy (Task-focused only)

Единственная стратегия. Смотрит текущий заказ → работает только с генератором, который может дать нужного существа.

**Каждый тик:**

1. **Claim rewards**
2. **Определяет нужные `creatureType`** из текущего задания
3. **Проверяет генераторы на два уровня:**
   - `outputs` — текущий уровень генератора выдаёт нужный тип прямо сейчас?
   - `lines` — генератор принадлежит к нужной "семье" (может выдать на более высоком уровне)?
4. **Если генератор не может выдать нужное** (только `lines` совпал):
   - Покупает второй генератор за rune1 (если есть деньги + свободная ячейка)
   - Мержит пары одинаковых генераторов → повышает уровень → открывает новые creature types
   - Кормит ВСЕ существа для EXP (высокоуровневых первыми)
   - Мержит ВСЕ пары существ (мержнутые дают больше EXP)
5. **Если `outputs` совпал** (генератор МОЖЕТ выдать нужное):
   - Кормит существ под заказ (частично — не ждёт полного набора)
   - Мержит только нужный тип до нужного уровня (с 70% шансом)
6. **Если нет задания** (level 1): фармит EXP со всеми генераторами
7. **Освобождает сетку** — если < 3 свободных ячеек, кормит самых дешёвых
8. **Спавнит все заряды** из подходящего генератора (все за тик)
9. **Заряжает** пустые генераторы

Не трогает генераторы, не связанные с текущим заказом.

## Данные

- **Генераторы** (`generators.json`): один генератор, 5 уровней. Level 1 = только Creature1. Level 2+ = Creature2 начинает появляться
- **Задания** (`tasks.json`): по уровням кракена. Level 2 = Creature1. Level 3+ = появляется Creature2
- **Связка**: генератор → `lines: ["Creature1", "Creature2"]` → может когда-нибудь выдать оба типа. `outputs` текущего уровня определяет что выдаёт прямо сейчас
- **Прокачка генераторов**: купить за rune1 → мердж двух одинаковых → level up → новые outputs
