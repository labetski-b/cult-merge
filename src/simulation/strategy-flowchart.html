RealisticStrategy — Phase State Machine

Engine вызывает decide() в цикле. Каждый вызов = микро-шаг. Цикл до done: true. Один tick = один значимый результат.

Tick = один значимый результат:
• Early game (kraken < 2): один level-up кракена
• Normal game: task → reward → invest → done

Движок вызывает стратегию в цикле, пока та не скажет «готово».
Engine loop: while (!done) { decision = strategy.decide(state); execute(decision.actions); }

Стратегия проходит 3 фазы последовательно: выполнить задание → забрать награды → вложиться в генераторы.
Phase state machine: decide() хранит phase: 'task' | 'reward' | 'invest'.

Когда существо скормлено и задание выполнено, domain автоматически создаёт следующее задание. Стратегия переключается на фазу наград.
Quest completion: domain feedEntity завершает квест и сразу генерирует следующий task. Engine вызывает strategy.onQuestCompleted() → phase переключается на 'reward'.

Подстраховка: если по какой-то причине задание не было создано — генерируем его в конце тика.
ensureAutoTask(): safety net в конце тика. Генерирует task только если domain не создал (например первый тик после kraken=2).

Когда не хватает мяса для зарядки генератора — стратегия запрашивает добычу мяса.
gatherMeat: стратегия эмитит gather_meat action с targetCost.

Все покупки и улучшения генераторов за один проход. Без повторных вызовов.
One-pass invest: investStep всегда возвращает done: true. Все покупки и мержи происходят за один проход: N × buy_generator + 1 × merge_cascade. Engine обрабатывает merge_cascade — каскадно мержит генераторы от Lv1 до targetLevel.

investGenerators() — оптимальные генераторы per creature

Цель: для каждого типа существа найти и обеспечить генератор с лучшей эффективностью (l1PerMeat). Это определяет, сколько Lv1-эквивалентов существ даёт генератор за единицу мяса.

l1PerMeat = Σ(chance × numCreatures × 2^(creatureLevel-1)) / chargeCost
Lv2 существо = 2× Lv1, Lv3 = 4× Lv1 и т.д. Считается через computeL1PerMeat() (= getExpectedL1PerCharge() / chargeCost).

Карта существ: creatureGenMap хранит для каждого типа существа — какой генератор его производит и насколько он эффективен. Карта сохраняется между тиками и используется фазой заданий для выбора генератора.
Техн.: Map<creatureType → { entityId, genId, genLevel, l1PerMeat }> — persistent, хранится в стратегии.

Всё за один проход: investStep всегда возвращает done: true. Покупки + мержи за один проход: buy + merge_cascade action. Engine обрабатывает merge_cascade — каскадно мержит генераторы одной family от Lv1 до targetLevel.

Без частичных покупок: upgrade покупается только если хватает бюджета на полную стоимость. Частичные покупки не производятся.

3 шага investGenerators:
• Шаг 1 — Добавить недостающие типы существ из квеста: если в задании есть существо, для которого нет записи в карте — создать заглушку. Техн.: { entityId:'', genId:0, genLevel:0, l1PerMeat:0 }
• Шаг 2 — Назначить лучший генератор с поля: для каждого существа в карте перебрать все генераторы на поле, вычислить эффективность и выбрать лучший. Если ни один генератор на поле не производит это существо — пропустить, покупка будет на шаге 3.
• Шаг 3 — Покупка и улучшение (от новейших к старейшим): зарезервировать бюджет для существ без генератора. Для каждого существа: найти конфиг генератора (доступного на текущем уровне кракена). Две ветки:
  — Case A (генератора нет): купить Lv1. Если рун не хватает на первые генераторы (уровни 1-2, критически важные) — докупить руны.
  — Case B (генератор есть): сравнить 3 варианта: улучшить (+1 уровень), купить новый Lv1, оставить как есть. Выбрать лучший по эффективности. Upgrade: рассчитать каскад покупок → N × buy_generator + merge_cascade. NewLv1: buy_generator.

calcGensNeeded(targetLevel, avail) — рекурсивный расчёт каскада

Задача: рассчитать, сколько генераторов Lv1 нужно купить, чтобы собрать генератор целевого уровня. Учитывает уже имеющиеся на поле генераторы, которые можно использовать для мержа.

avail[i] = количество генераторов уровня (i+1) на поле. Мутирует массив при «использовании» генераторов.

Рекурсия need(lv):
• lv == 1 → нужен один генератор, return 1 (одна покупка)
• avail[lv-2] >= 2 → есть два готовых генератора для мержа, return 0 (покупать не надо)
• Иначе: не хватает генераторов, missing = 2 - avail[lv-2], обнулить avail, рекурсивно рассчитать для каждого недостающего

Пример: targetLevel=3, avail=[1,0] (один Lv1 на поле):
need(3) → need(2) × 2 → need(2): avail[0]=1, missing=1, need(1)=1. Второй need(2): avail[0]=0, missing=2, need(1)×2=2. Итого: 3 покупки Lv1.
