# Session Context: Balance Research

Этот файл — полный контекст сессии исследования баланса. При начале новой сессии Claude должен прочитать этот файл для восстановления контекста.

## Как работать с этим проектом

### Роль Claude
- **Оркестратор**: сам код не пишет, запускает субагентов (model: opus) для исследования и кодинга
- Валидирует результаты субагентов перед применением
- Ведёт документацию в `BALANCE_RESEARCH.md` и README экспериментов
- Перед выполнением задач уточняет у пользователя неясности

### Структура экспериментов
- `src/data/experiments/BALANCE_RESEARCH.md` — мастер-файл всего исследования
- `src/data/experiments/<N>.<name>/` — папки экспериментов с нумерацией
- Каждый эксперимент: `README.md` (документация) + JSON файлы (данные)
- `src/data/experiments/baseline/` — снапшот production баланса

### Скрипты
- Симуляция: `npx tsx --tsconfig tsconfig.app.json scripts/run-sim.ts [ticks] [filter]`
- Эксперимент: `npx tsx --tsconfig tsconfig.app.json scripts/run-experiment.ts <name> [ticks] [filter]`
- `run-experiment.ts` поддерживает override: generators.json, chapters_data_analytics.json, creatures.json
- Comparison table включает: Final level, Tasks, EXP, Charges, Sessions, Eyes, Chapter + Chapter Milestones

## Часть 2: Meat-to-Eyes Economy — СИМУЛЯЦИЯ ПРОВЕДЕНА

**Папка**: `2.meat-to-eyes-economy/`
**Статус**: симуляция завершена с положительными результатами; решение о применении — следующий шаг

### Контекст
Часть 1 — фиксированная база. Часть 2 дизайнит экономику мяса→глаз поверх неё:
- Сколько eyes на 1 meat в каждой фазе игры
- Efficiency генераторов (chargeCost, numCreatures, eyesMultiplier)
- Auto-quests влияние на динамику
- Проверка: скорость прохождения уровней и чаптеров должна плавно замедляться

### Архитектура экономики (из исследования)

**Eyes — 100% task-gated**: единственный источник eyes — задания (tasks). Кормление даёт только EXP.
- resMultiplier = 2 всегда (и mandatory, и auto tasks)
- expMultiplier = 0 всегда (задания не дают бонусный EXP)
- Mandatory tasks: уровни кракена 2-7. После — только auto tasks.
- Auto-tasks предпочитают существ из новейших генераторов (54.5% веса самому старшему типу)
- 50% шанс "снайперского" задания на L6+ существо с поля

**Системные проблемы**:
1. Efficiency внутри генератора ПАДАЕТ — chargeCost растёт быстрее avg_eyes
2. Level 2 spike — у Gen5-8 cost на L2 = cost на L1, но L2 дроп гораздо лучше
3. Gen1.5 хуже Gen1.1 — апгрейд наказывает игрока
4. Диапазон от 1.22 до 6.88 — хаотичный, без тренда
5. Линейки изолированы — Gen1 max не сравним с Gen2, нет "перекрытия"
6. Gen5 L2: chargeCost 8→7 — единственный генератор с удешевлением при апгрейде

### Решение: восходящая кривая с перекрытиями

**Дизайн-принцип**: efficiency растёт внутри каждого генератора (L1→L5), поздние уровни линейки N перекрываются с ранними уровнями линейки N+1.

**Изменения в creatures.json**:
- Creature1: eyesMultiplier 1 → **3** (дать Gen1 granularity для integer costs)
- Creature2: eyesMultiplier 2 → **6** (пропорционально, соотношение 1:2 сохранено)

### Побочные эффекты eyesMult

- Sell price Creature1 L1: 2 eyes → 6 eyes. Ранняя экономика получает 3x eyes от Gen1.
- Но chargeCost Gen1.1 тоже 3x (1→3). Итоговая efficiency та же (2.0).
- Абсолютные числа eyes больше — может потребовать пересмотра quest rewards и early-game eyes costs.
