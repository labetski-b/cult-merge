# Experiment: gen-efficiency-curve

## Гипотеза

Эффективность генераторов (eyes/meat) должна **расти внутри каждого генератора** по мере
апгрейда и **перекрываться между линейками** — поздние уровни линейки N сравнимы с ранними
уровнями линейки N+1. Это создаёт плавную восходящую кривую от Gen1.1 (~2.0) до Gen8.5 (~6.9).

## Метод

### Три рычага баланса

| Рычаг | Влияние на efficiency | Используем? |
|-------|----------------------|-------------|
| `chargeCost` | Прямое (знаменатель: eff = avg_eyes / cost) | Да, основной |
| `eyesMultiplier` | Прямое (числитель: увеличивает avg_eyes) | Да, для Gen1 |
| `numCreatures` | **Никак** (сокращается). Влияет на объём, не на eff | Нет |

### Формула эффективности

```
Efficiency = avg_eyes_per_creature / chargeCost
```

### Проблема Gen1 и integer costs

С eyesMult=1 у Creature1, eyes = 2 или 4. chargeCost — целое число. Доступные efficiency:
- cost=1 → eff=2.0, 2.92, 3.64, 4.80, 6.08 (монотонный рост, но Gen1.5 выше Gen8!)
- cost=2 → eff=1.0, 1.46, 1.82, 2.40, 3.04 (ниже Gen1.1 на L2)

Нет промежуточных значений. **Решение**: поднять eyesMult: Creature1 1→3, Creature2 2→6.
Утроенные eyes дают больше вариантов integer cost для плавной кривой.

### Порядок анлока

Генераторы анлочатся по Kraken level. Уровни внутри генератора — через **мердж**
(два Gen1.1 → Gen1.2, два Gen1.2 → Gen1.3 и т.д.). Это экспоненциальная стоимость:

- L1: 1 покупка
- L2: 2 покупки
- L3: 4 покупки
- L4: 8 покупок
- L5: 16 покупок

Поэтому L4-L5 текущего генератора обычно доступны ПОЗЖЕ, чем L1 следующего.

| Kraken | Генератор | Purchase Cost |
|--------|-----------|---------------|
| 1 | Gen1 | 5 rune1 |
| 7 | Gen2 | 5 rune2 |
| 13 | Gen4 | 20 rune2 |
| 18 | Gen5 | 40 rune1 |
| 23 | Gen6 | 40 rune2 |
| 28 | Gen7 | 60 rune1 |
| 33 | Gen8 | 60 rune2 |

Примерная хронология (с учётом мерджа):

```
kr1:  Gen1.1 → Gen1.2 → Gen1.3
```

### Системные проблемы

1. **Эффективность внутри генератора ПАДАЕТ** — chargeCost растёт быстрее avg_eyes
2. **Level 2 spike** — у Gen5-8 cost на L2 = cost на L1, но L2 дроп гораздо лучше
3. **Gen1.5 хуже Gen1.1** — апгрейд наказывает игрока
4. **Диапазон от 1.22 до 6.88** — хаотичный, без тренда
5. **Линейки изолированы** — Gen1 max не сравним с Gen2, нет "перекрытия"

## Дизайн-принцип

**Восходящая кривая с перекрытиями.** Внутри каждого генератора efficiency растёт от L1 к L5.
Поздние уровни линейки N перекрываются с ранними уровнями линейки N+1:

```
Gen1:  2.00 ── 2.19 ── 2.73 ── 2.88 ── 3.04
Gen2:                           2.67 ── 2.92 ── 2.91 ── 3.20 ── 3.47
Gen4:                                                   3.56 ── 3.96 ── 4.07 ── 4.36 ── 4.65
Gen5:                                                                    4.00 ── 4.35 ── 4.48 ── 4.80 ── 5.12
Gen6:                                                                                             5.20 ── 5.44 ── 5.60 ── 5.57 ── 5.94
Gen7:                                                                                                              5.83 ── 5.95 ── 6.13 ── 6.18 ── 6.59
Gen8:                                                                                                                              6.14 ── 6.50 ── 6.69 ── 6.79 ── 6.88
```

**Принцип перекрытия:**
- Gen1.5 (3.04) ≈ Gen2.2 (2.92) — максед Gen1 = середина Gen2
- Gen2.5 (3.47) ≈ Gen4.1 (3.56) — максед Gen2 = начало Gen4
- Gen4.5 (4.65) > Gen5.1 (4.00) — максед Gen4 > начало Gen5
- Gen5.5 (5.12) ≈ Gen6.1 (5.20) — максед Gen5 ≈ начало Gen6
- Gen6.5 (5.94) ≈ Gen7.1 (5.83) — максед Gen6 ≈ начало Gen7
- Gen7.5 (6.59) > Gen8.1 (6.14) — максед Gen7 > начало Gen8

**Структурное ограничение L2→L3:**
У всех генераторов avg_eyes L2→L3 растёт всего на ~3% (44.80 vs 43.52 для Gen4/5).
При целых costs это означает: cost L3 должен быть = cost L2, иначе eff ПАДАЕТ.
В Gen2 это даёт микро-дип 2.92→2.91 (0.3%), в Gen6 — 5.60→5.57 (0.5%). Принимаем.

## Побочные эффекты eyesMult

Изменение eyesMult Creature1/2 влияет на:
- **Sell price**: Creature1 L1 продаётся за 6 eyes вместо 2. Ранняя экономика получает 3x eyes от Gen1.
- **Но cost тоже 3x**: Gen1.1 стоит 3 meat/charge вместо 1. Итоговая efficiency та же (2.0).
- **Абсолютные числа больше**: игрок оперирует числами 6-24 вместо 2-8 в ранней игре.
- Может потребовать пересмотра quest rewards и eyes costs в ранней игре.

## Результат (seed=42, 5000 ticks)

```
  Metric                       Baseline   Experiment        Δ       %
  ────────────────────────────────────────────────────────────────────
  Final level                        34           33       -1    -3%
  Tasks completed                   354          340      -14    -4%
  Total EXP                       74217        73665     -552    -1%
  Total charges                    1076          983      -93    -9%
  Final session                     122          116       -6    -5%
  Avg charges/session              8.82         8.47    -0.35    -4%
```

### Анализ

- **Level 34→33**: разница в 1 уровень за весь прогон. Минимальное влияние на прогрессию.
- **Charges -9%**: часть генераторов стала дороже per charge (Gen5.2: 7→10, Gen6.2: 12→13, Gen8.2: 17→18). Но efficiency выровнена — каждый потраченный meat даёт предсказуемый return.
- **EXP -0.7%**: практически идентично. Creature drops не менялись (кроме eyes).
- **Tasks -4%**: небольшое замедление из-за чуть меньшего количества charges.

### Вывод

Эксперимент **выравнивает efficiency кривую** с минимальным влиянием на общую прогрессию (-3% по уровню). Спайки устранены, efficiency внутри каждого генератора растёт, линейки перекрываются. Основной tradeoff — 9% меньше charges (генераторы расходуются чуть медленнее).

## Статус

**Симуляция проведена.** Результаты положительные — кривая выровнена, прогрессия сохранена.
