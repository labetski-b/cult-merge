# Experiment: Meat-to-Eyes Economy (Part 2)

## Цель

Устранить аномалии в efficiency кривой генераторов (eyes/meat). Конкретно:
- Убрать **L2 spikes** у Gen5-Gen8 (efficiency скачком +81-107% при апгрейде, из-за cost L2 ≤ cost L1)
- Починить **Gen1 L4-L5 drops** (efficiency падает -37% и -16% из-за cost 5→10 при росте output ×1.58-1.69)
- Сохранить Part 1 alignment (Ch16≈L49, Ch17≈L54) и session budget (7-10 charges/session)

## Формулы

### Efficiency (eyes/meat) — полная разрядка генератора

```
total_eyes_per_charge = avg_eyes_per_creature × numCreatures
efficiency = total_eyes_per_charge / chargeCost
```

Где `avg_eyes_per_creature` — средневзвешенное по output probabilities:

```
avg_eyes = Σ(chance_i × eyesMult_i × baseEyes[level_i])
```

baseEyes: L1=2, L2=4. eyesMult зависит от типа существа.

### Output probabilities (одинаковые для всех генераторов)

| Gen Level | Outputs |
|-----------|---------|
| L1 | CrA.1: 100% |
| L2 | CrA.1: 54%, CrA.2: 36%, CrB.1: 10% |
| L3 | CrA.1: 42%, CrA.2: 28%, CrB.1: 18%, CrB.2: 12% |
| L4 | CrA.1: 20%, CrA.2: 20%, CrB.1: 30%, CrB.2: 30% |
| L5 | CrA.1: 4%, CrA.2: 6%, CrB.1: 36%, CrB.2: 54% |

### numCreatures по уровням

L1: 15, L2: 20, L3: 25, L4: 30, L5: 40

### Рост total output между уровнями

Для генераторов с одинаковым eyesMult обеих линий (Gen4-Gen8):

| Переход | Рост total output | Источник роста |
|---------|-------------------|---------------|
| L1→L2 | **×1.813** | numCr 15→20, лучший дроп (+36% avg_eyes) |
| L2→L3 | ×1.287 | numCr 20→25, avg_eyes +2.9% |
| L3→L4 | ×1.286 | numCr 25→30, avg_eyes +7.1% |
| L4→L5 | ×1.422 | numCr 30→40, avg_eyes +6.7% |

Для Gen1 (eyesMult 1/2) и Gen2 (eyesMult 4/8) — асимметричные линии, рост выше.

## Ограничения дизайна

1. **Dual-resource**: charges дают и eyes (через tasks) и EXP (через кормление). eyesMult масштабирует только eyes. Нельзя менять chargeCost для компенсации eyesMult — это убивает EXP.
2. **Session budget**: 7-10 зарядов суммарно за сессию (5 Get Meat × meat_per_chapter / avg_cost).
3. **Part 1 alignment**: Ch16=L49, Ch17=L54 должно сохраниться.
4. **Integer costs**: chargeCost — целое число. Ограничивает гранулярность.

### Реальные проблемы baseline

1. **Gen1 L2→L3 drop** (-22%): cost удваивается (1→2), total output растёт только +56%. Структурная проблема — нет целого числа между 1 и 2.
2. **Gen5 L2 spike** (+107%): cost ПАДАЕТ (8→7!) при росте output ×1.81. Аномалия.
3. **Gen6-8 L2 spikes** (+81%): cost L2 = cost L1, при росте output ×1.81.
4. **Gen2 L4 spike** (+58%): cost L3 = cost L4 = 5, при росте output ×1.58.

**Gen4 — уже монотонный**, проблем нет.

## Отвергнутые подходы

### v1: eyesMult + chargeCost

Creature1 eyesMult 1→3, Creature2 2→6, Gen1 chargeCost 1→3 для компенсации.

**Ошибка**: chargeCost↑ убивает EXP (expMultiplier не масштабируется с eyesMult). Charges в 3 раза меньше → creatures в 3 раза меньше → EXP -76%.

**Результат**: 50K тиков, Final level 164→56 (-66%). Каскадный коллапс.

### v2: Gen1 all cost=1

Gen1 chargeCost=1 на всех уровнях. Gen2-Gen8 — "step-up-then-plateau".

**Ошибка**: Gen1 cost=1 перетягивает мясо на себя (eyesMult=1, низкий return). В Ch17 (137 meat/session) можно сделать 100+ зарядов Gen1. Ломает session budget и eye-chapter alignment.

**Результат**: EXP +4.8%, но eyes -20%. Ch16 сместился с L49 на L52, Ch17 с L54 на L60.

### v3: Неверная метрика efficiency

Формула без numCreatures: `eff = avg_eyes_per_creature / chargeCost`. Не учитывает что L1=15 существ, L5=40 существ.

**Ошибка**: с этой метрикой Gen4-Gen8 казались "сломанными" (efficiency падала при апгрейде). На самом деле рост numCreatures компенсирует рост cost, и Gen4, Gen6-8 уже монотонны в baseline. Эксперимент фиксил несуществующие проблемы в Gen4, ухудшая Gen4 L1-L2.

**Результат**: симуляция была приемлемой (+2 level, Ch16=L49), но Gen4 менялся без необходимости, а Gen2 L4 spike не фиксился.

### v4: Трёхсторонний interaction effect

Правильная метрика (с numCreatures), минимальные изменения: Gen2 L4-L5 fix, Gen4 baseline, Gen5-Gen8 L2 spike fix.

**Ошибка**: три одновременных изменения (Gen2 L4: 5→6, Gen4 reverted to baseline, Gen5 L1: 9→8) создают **три-way interaction** в стратегии симулятора. Каждое изменение по отдельности — +2-3 level. Любая пара — +2-5 levels. Все три вместе — коллапс -89 levels.

Систематическое тестирование (7 вариантов):

| Тест | Gen2 | Gen4 | Gen5 L1 | Δ Level |
|------|------|------|---------|---------|
| Только Gen4→baseline | v3 | baseline | 9 | +2 |
| Только Gen2→v4 | v4 | v3 | 9 | +2 |
| Только Gen5 L1→8 | v3 | v3 | 8 | +3 |
| Gen4+Gen5 | v3 | baseline | 8 | +3 |
| Gen2+Gen4 | v4 | baseline | 9 | +3 |
| Gen2+Gen5 | v4 | v3 | 8 | +5 |
| **Все три** | **v4** | **baseline** | **8** | **-89** |

**Вывод**: нельзя одновременно менять Gen2 cost + Gen4 shape + Gen5 L1. Три изменения вместе создают ресурсный deadlock в стратегии симулятора.

## Текущий подход: v5

### Принцип

Фиксить только Gen5-Gen8 L2 spikes. Gen1, Gen2, Gen4 — оставить на baseline.

Спайки Gen2 L4 (+58%) и Gen6-8 L2 (+81%) — это не проблема для игрока. Spike = апгрейд даёт непропорционально хороший return. Drop — настоящая проблема (апгрейд наказывает).

| Проблема | Генератор | Решение v5 |
|----------|-----------|------------|
| L2 spike +107% | Gen5 | Поднять L2: 7→11, flat L3-L5=11 |
| L2 spike +81% | Gen6 | Снизить L1: 12→11, поднять L2: 12→14, flat L3-L5=14 |
| L2 spike +81% | Gen7 | Снизить L1: 15→13, поднять L2: 15→17, flat L3-L5=17 |
| L2 spike +81% | Gen8 | Снизить L1: 17→15, поднять L2: 17→19, flat L3-L5=19 |
| L4 spike +58% | Gen2 | Оставить baseline (spike не вредит игроку) |
| Gen1 L3 drop | Gen1 | Оставить (структурная, нет integer fix) |
| Gen4 monotonic | Gen4 | Оставить baseline (уже OK) |

### Паттерн: "step-up-then-plateau"

Total output растёт ×1.81 на L1→L2. Cost L2 = ~L1 × 1.4 → efficiency +32-43%. Далее L3-L5 output растёт ×1.29, cost остаётся flat → efficiency +29% на каждом шаге.

### Trade-offs

- ✅ Gen5-Gen8 efficiency монотонна, L2 spikes убраны
- ✅ Level +2, EXP +1.4%, charges +2.9%
- ✅ Gen2 L4 spike оставлен (spike = reward, не проблема)
- ✅ Total cost -2% (экономия за счёт cheaper L4-L5)
- ⚠️ Part 1 alignment сместилась: Ch16 L46 (было L49), Ch17 L52 (было L54)
- ⚠️ Cause: Gen6-8 L1 дешевле → больше зарядов → больше eyes → главы быстрее
- ⚠️ Gen1 L3 drop (-22%) остаётся (структурная проблема)
