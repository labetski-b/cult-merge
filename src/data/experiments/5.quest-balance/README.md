# Эксперимент 5: Баланс квестов — Budget-Based Auto-Quest Algorithm

**Статус:** 📐 Дизайн нового алгоритма
**Дата:** 2026-03-04
**Фокус:** Полная переработка `generateAutoTask` на основе бюджета глаз и стоимости в спаунах

---

## Концепция

Текущий алгоритм генерирует квест "от ингредиентов" (случайный тип × случайный уровень × случайный count), не зная сколько глаз этот квест даст и сколько спаунов потребует. Результат — хаос: от 4 до 12,000 глаз подряд, от 0.1 до 12+ спаунов.

**Новый подход: от бюджета к квесту.**

1. Определить **целевой бюджет глаз** для этого квеста (плавно растёт + пила внутри батча)
2. Выбрать **тип существа** (с учётом новинок и разнообразия)
3. Подобрать **level × count** чтобы попасть в бюджет И уложиться в **≤3 спауна генератора**

## Принцип 1: Бюджет глаз — плавный рост + пила

### Базовый бюджет по Kraken Level

Piecewise-linear интерполяция между anchor points (привязаны к фазам генераторов):

```
Level →  2    6    9   12   17   22   27   32   49
Budget→ 10   60  209  429  825 1331 2056 3156 5773
```

Формула: линейная интерполяция между соседними anchors.

### Пила внутри батча из 7 квестов

```
questIndex % 7 →  0     1     2     3     4     5     6
multiplier    → 0.65  0.65  0.93  0.93  1.22  1.22  1.40
```

- Позиции 0-1: **разогрев** (65% бюджета) — лёгкие квесты
- Позиции 2-3: **стандарт** (93%) — нормальные
- Позиции 4-5: **челлендж** (122%) — сложные
- Позиция 6: **босс** (140%) — самый тяжёлый

Среднее = 1.0 ровно. Игрок чувствует ритм: передышка → нарастание → пик → сброс.

### Пример L10 (baseBudget = 282)

| # | Множитель | Target Eyes | Ощущение |
|---|-----------|-------------|----------|
| 0 | ×0.65 | 183 | Лёгкий |
| 1 | ×0.65 | 183 | Лёгкий |
| 2 | ×0.93 | 262 | Средний |
| 3 | ×0.93 | 262 | Средний |
| 4 | ×1.22 | 344 | Сложный |
| 5 | ×1.22 | 344 | Сложный |
| 6 | ×1.40 | 395 | Босс |

## Принцип 2: Стоимость в спаунах ≤ 3

### Формула стоимости

```
spawnCost = totalL1equiv / l1equivPerCharge[creatureType]

где:
  totalL1equiv = count × 2^(level - 1)
  l1equivPerCharge = ожидаемое кол-во L1-эквивалентов данного типа за один заряд текущего генератора
```

## Принцип 3: Выбор типа существа

### Приоритеты

1. **Новинка (introduction)** — если разблокирован генератор, чьи существа ещё ни разу не были в квесте → первый квест = L1 × 1 нового типа. Отслеживаем через `autoTaskLineCompletions[type] === 0 || undefined`.

2. **Ramp-up** — для линейки с < 5 выполненных квестов, используем фиксированное расписание:
   ```
   completions: 0 → L1×1 (introduction)
   completions: 1 → L1×2
   completions: 2 → L2×1
   completions: 3 → L2×2
   completions: 4 → L3×1
   ```
   Это обучает игрока новому существу постепенно.

3. **Обычный выбор** — после ramp-up, выбор типа с весами по "свежести":
   - Существа из последнего разблокированного генератора: вес 40%
   - Существа из предыдущего генератора: вес 35%
   - Старые существа: вес 25% (убывающий)
   - Антидубль: не повторять тип предыдущего квеста (90% шанс)

### Зачем старые существа всё ещё нужны

Creature1 на L20 кракена — это не "2 глаза за L1", а "Creature1 L7-L8 за 256-512 глаз". Старые существа при высоком уровне генератора дают высокоуровневые мерджи. Но их **доля** должна снижаться с появлением новых генераторов.

## Принцип 4: Подбор level × count под бюджет

### Алгоритм

```
Input: targetEyes, creatureType, generator (on field)
Output: { level, count }

1. eyesMult = creature.eyesMultiplier (1, 2, 4, 8, 16...)
2. l1perCharge = expectedL1equiv(generator, creatureType)

3. Перебираем все допустимые (level, count) пары:
   for level = 1..maxLevel:
     for count = 1..4:
       eyes = baseEyes[level-1] * eyesMult * count * resMultiplier
       l1needed = count * 2^(level-1)
       spawns = l1needed / l1perCharge

       if spawns > 3.0: skip  // Принцип 2: не больше 3 спаунов

       score = |eyes - targetEyes| / targetEyes  // Отклонение от бюджета

       Сохраняем пару с минимальным score

4. Если ничего не найдено в пределах ≤3 спаунов → снижаем level до максимально возможного при 3 спаунах

5. Допустимое отклонение: ±40% от targetEyes (jitter для разнообразия)
```

### Пример работы

**Kraken L10, questIndex=4 (челлендж), targetEyes=344, генератор Gen2 L3:**

Creature3 (eyesMult=4, l1perCharge=24.5):
| level | count | eyes | spawns | deviation |
|-------|-------|------|--------|-----------|
| L3 | 2 | 128 | 0.33 | -63% ❌ |
| L4 | 2 | 256 | 0.65 | -26% ✅ |
| L5 | 1 | 256 | 0.65 | -26% ✅ |
| L5 | 2 | 512 | 1.31 | +49% ❌ |
| L4 | 3 | 384 | 0.98 | +12% ✅ best |
| L6 | 1 | 512 | 1.31 | +49% ❌ |

→ Выбираем **Creature3 L4 × 3** (384 eyes, 0.98 спаунов, +12% от бюджета)

Creature4 (eyesMult=8, l1perCharge=10.5):
| level | count | eyes | spawns | deviation |
|-------|-------|------|--------|-----------|
| L3 | 1 | 128 | 0.38 | -63% ❌ |
| L3 | 2 | 256 | 0.76 | -26% ✅ |
| L4 | 1 | 256 | 0.76 | -26% ✅ |
| L3 | 3 | 384 | 1.14 | +12% ✅ best |
| L4 | 2 | 512 | 1.52 | +49% ❌ |

→ Выбираем **Creature4 L3 × 3** (384 eyes, 1.14 спаунов, +12% от бюджета)

Оба варианта дают ~384 eyes и ~1 спаун. Разные существа, разные уровни, **одинаковый бюджет**.

## Принцип 5: Mandatory квесты остаются до L7

- **L2-L5:** текущие mandatory без изменений (туториал + введение Creature2)
- **L6-L7:** обновлённые mandatory (сниженная сложность, введение Creature3/4)
- **L8+:** полностью авто-квесты с budget-based алгоритмом

Mandatory квесты остаются инструментом ручной регулировки для раннего геймплея.

---

## Что убирается из старого алгоритма

| Старое | Проблема | Новое |
|--------|----------|-------|
| `calcMaxLevel` (теоретический) | Завышает возможности | Заменяем на `spawnCost ≤ 3` |
| `lineCompletions / divisor` + `maxLvl + bonus` | Убегающая сложность | Бюджет растёт плавно через anchors |
| Random count 1-4 (uniform) | Не связан с наградой | count подбирается под бюджет |
| Random level в диапазоне | Может попасть в невозможное | level подбирается под бюджет + ≤3 спауна |
| Seniority weights 30/15/7... | Перекос к новым, но старые платят копейки | Weights по "свежести" + бюджет нормализует reward |
| Нет понятия "стоимости" квеста | Квест может стоить 0.1 или 12 спаунов | Жёсткий cap: ≤3 спаунов |

---

## Что сохраняется

- **50% chance на high-level creature с поля** (Step 0) — хорошая механика "уборки"
- **Anti-duplicate** (не повторять предыдущий квест)
- **resMultiplier: 2** — квестовый бонус к глазам
- **Mandatory до L7** — ручной контроль раннего геймплея

## Принцип 6: Мульти-creature квесты (fresh + filler)

### Концепция

Квест может содержать **два разных типа существ**:
- **Fresh** (из нового генератора) — основной прогресс, дорогие спауны, ~60% бюджета
- **Filler** (из старого генератора) — геймплей/engagement, дешёвые спауны, ~40% бюджета

### Когда генерируются

- 2+ генератора на поле
- Все текущие типы существ прошли ramp-up (≥5 квестов)
- ~50% квестов (остальные 50% — single-creature)

### Пример (KL13, Gen1 L5 + Gen4 L1, targetEyes = 508)

**Fresh (60% = 305 eyes):** Creature7 L2 × 1 = 128 eyes (Gen4, 0.13 спаунов)
**Filler (40% = 203 eyes):** Creature2 L6 × 1 = 256 eyes (Gen1, 0.56 спаунов)
**Итого:** 384 eyes, ~0.7 спаунов суммарно

### Зачем

1. **Больше геймплея** — игрок работает с двумя генераторами одновременно
2. **Знакомые существа остаются актуальны** — Creature1/2 не исчезают из квестов
3. **Нормализация сложности** — filler-часть выполняется быстро, fresh-часть даёт challenge
4. **Smooth transition** — при открытии нового генератора old creatures мягко вытесняются, а не исчезают мгновенно
