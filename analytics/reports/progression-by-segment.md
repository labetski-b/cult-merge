# Прогрессия игроков по сегментам

**Дата анализа:** 2026-02-27
**Когорта:** install_date 13 января — 13 февраля 2026 (Android)
**Таблица:** `wazzitude.events1268`

---

## Методология

### Когорта
Взяты пользователи с `install_date` между 2026-01-13 и 2026-02-13. Это даёт окно от 2 до 6.5 недель игры — достаточно для прогрессии до высоких уровней, при этом данные свежие.

### Сегментация
Пользователи разделены по **uuid** (user identifier) на три группы:

| Сегмент | Определение | Размер когорты |
|---------|-------------|----------------|
| **payer** | Имеет хотя бы одно событие `af_purchase` | ~15,000 |
| **ad_watcher** | Имеет `af_rewarded`, но нет `af_purchase` | ~302,000 |
| **free** | Нет ни покупок, ни rewarded ads | ~306,000 |

### Ключевое открытие при сборе данных

**`euid` — это ID события, не пользователя.** Каждое событие получает уникальный `euid` (ratio events/euid ≈ 1.01). Настоящий user identifier — поле **`uuid`**, которое связывает все типы событий одного пользователя (merge_level_up, af_purchase, af_rewarded, session_start и т.д.).

### Метрика
- `playing_time_in_game` (в минутах) — накопленное время в игре на момент события
- Показаны: медиана (p50), нижний квартиль (p25), верхний квартиль (p75)

## Сравнение: Merge Level vs Chapter

**Payers прогрессируют по-разному в двух системах:**
- **Merge Level**: payers МЕДЛЕННЕЕ ad_watchers (на 5-10%)
- **Chapter**: payers БЫСТРЕЕ ad_watchers (на 5-8% с chapter 6+)

Это логично: покупки дают ресурсы для idle-прогрессии (главы), но мердж-борд требует ручных действий (мерджи, зарядки, квесты), которые не ускоряются деньгами.

## Запросы

### Merge Level Progression
```sql
SELECT
    toUInt32(ep_level) AS merge_level,
    multiIf(
        uuid GLOBAL IN (
            SELECT uuid FROM wazzitude.events1268
            WHERE event_name = 'af_purchase'
              AND install_date BETWEEN '2026-01-13' AND '2026-02-13'
              AND is_test = 0
        ), 'payer',
        uuid GLOBAL IN (
            SELECT uuid FROM wazzitude.events1268
            WHERE event_name = 'af_rewarded'
              AND install_date BETWEEN '2026-01-13' AND '2026-02-13'
              AND is_test = 0
        ), 'ad_watcher',
        'free'
    ) AS segment,
    uniq(uuid) AS users,
    quantile(0.5)(playing_time_in_game) / 60 AS median_min,
    quantile(0.25)(playing_time_in_game) / 60 AS p25_min,
    quantile(0.75)(playing_time_in_game) / 60 AS p75_min
FROM wazzitude.events1268
WHERE event_name = 'merge_level_up'
  AND install_date BETWEEN '2026-01-13' AND '2026-02-13'
  AND is_test = 0
GROUP BY merge_level, segment
ORDER BY merge_level, segment
```

## Технические заметки

- **User identifier**: поле `uuid` (НЕ `euid`!). `euid` = event UUID, уникален для каждой строки
- **Сегментация через GLOBAL IN**: subquery для payer/ad_watcher выполняется отдельно, результат распространяется на все шарды
- **install_date**: поле пользователя, одинаково на всех его событиях
- **playing_time_in_game**: кумулятивное время в секундах, конвертируем в минуты (/60)
- **Аномалия free на level 40+**: единичные пользователи с playing_time ~100 мин на уровне 50 — вероятно, читеры
